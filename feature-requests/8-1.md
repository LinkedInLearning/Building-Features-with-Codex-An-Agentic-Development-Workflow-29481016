# Feature 2: Dashboard metrics

## 1. The problem

Team leads want a quick read on the queue without counting cards. When they filter to one customer or one priority, the numbers should describe what they're looking at.

## 2. Expected behavior

- [ ] Four metric cards appear above the ticket list:
  - **Matching tickets:** how many tickets are visible
  - **Open:** visible tickets with status Open
  - **High priority:** visible tickets with priority High
  - **Unassigned:** visible tickets with no assignee
- [ ] The metrics are calculated from the tickets **currently visible after filtering**, not the full list.
- [ ] Changing search, status, or priority updates all four cards right away.
- [ ] Clear filters returns the cards to the totals for the full list.

## 3. Limits

- Non-goals: charts, trends over time, clickable cards.
- Constraints: no new dependencies. Reuse the filtered list Feature 1 already produces. No second filtering system.
- Must keep working: search, filters, result count, and empty state from Feature 1.

## 4. How we'll prove it works

- Tests: test the counting logic on its own, and test that the metrics come from the filtered list rather than the original `tickets` array.
- Manual check: filter to High priority and confirm the High priority card matches Matching tickets. Then clear filters and confirm the totals come back.
